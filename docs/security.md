# 安全与访问控制

## 管理端

- 初始化状态、首次初始化和登录是公开入口；首次初始化完成后，其余管理 API 要求会话 Cookie。
- 配置、规则等写操作还要求 `X-BRPX-CSRF`。
- 会话 Cookie 为 `HttpOnly`、`SameSite=Strict`，HTTPS 请求下同时启用 `Secure`。
- 管理密码使用 Argon2 哈希；最短 12 个字符。
- 密码可在“服务配置”页轮换；更新成功后除当前浏览器外的管理会话立即失效。
- 建议通过防火墙、VPN 或反向代理来源限制保护 `/admin/`，不要直接暴露到整个互联网。

## 规则主体

| 类型 | 保存内容 | 示例 |
|---|---|---|
| `uid` | Bilibili 数字 UID | `123456` |
| `ip` | 标准化单个 IPv4/IPv6 | `203.0.113.8` |
| `cidr` | 标准化网段 | `203.0.113.0/24` |
| `token` | SHA-256 指纹 | Web 输入 access key，后端只保存指纹 |

规则支持 `allow` 和 `deny`、作用范围、原因、启停状态和过期时间。主体越具体优先级越高：令牌、UID、精确 IP、CIDR。同一优先级同时命中时拒绝优先。

范围可为 `all`、`playurl`、`tv`、`search`、`season`、`subtitle` 或 `accesskey`。过期与停用规则不参与匹配。

## 审计脱敏

审计只保存请求 ID、时间、来源 IP、UID、接口、地区、剧集 ID、番剧标题、HTTP/业务状态、耗时、缓存/上游和规则命中。业务响应码从进程内响应元数据提取，内部标记不会发送给客户端。以下内容不会进入审计表：

- 原始 access key
- Cookie 和 Authorization
- 请求签名
- 完整敏感查询串
- 管理密码和配置秘密

番剧标题由异步任务补全，实际元数据请求通过 Semaphore 限制为最多 4 个；上游失败不会阻塞播放请求。审计队列容量为 2048，满时请求仍继续，仪表盘会增加丢弃计数。

## 备份

`data/brpx.db` 包含密码哈希、会话、规则和审计，应按敏感数据保护。备份前停止服务或使用 SQLite 在线备份工具，避免只复制 WAL 模式下的不完整主文件。
